Hi HN. I built a Chrome extension that turns the page you're reading — including your claude.ai conversations and YouTube transcripts — into clean Markdown and either appends it directly to your project's context files (CLAUDE.md, plus .cursorrules / .windsurfrules if you run several agents) OR exposes it to Claude Code on demand via a bundled MCP server. And yes — it parses HN item pages, so it can capture this very thread.

Why: the existing workflow leaks context badly. You spend an hour brainstorming with claude.ai, then switch to your terminal where Claude Code is running, and the agent knows none of it. claude.ai share links 403 from outside the browser session. Handing the agent URLs doesn't reliably work (many models can't fetch, and login-walled or JS-rendered pages come back empty). Copy-pasting brings ads and sidebars. And once CLAUDE.md grows past ~30k tokens, Anthropic's own guidance is that Claude starts ignoring your instructions.

Two delivery modes:

1. Direct append. Pick a file once with the File System Access API; every capture appends directly. URL-pattern routing sends github.com/anthropic/* to one file, zenn.dev/* to another, claude.ai/chat/* to whichever project you're on. A single route can fan out to multiple targets at once (CLAUDE.md + .cursorrules + .windsurfrules), and partial write failures are surfaced instead of swallowed.

2. MCP-on-demand. Captures land as individual Markdown files; a bundled MCP server exposes get/list/search to Claude Code, so the agent pulls what it needs and CLAUDE.md stays small. Re-capturing the same claude.ai conversation overwrites in place (stable id), so you don't accumulate snapshot silos. A CCC_MCP_TOOLS env var trims the exposed tool set — the lean profile cuts ~52% of the per-turn tool-definition token cost, minimal ~82%.

Site-specific parsers for GitHub issues/PRs, Stack Overflow, MDN, YouTube (transcript + chapters as [mm:ss] headings), Reddit (JSON endpoint, not the shreddit DOM), HN (comment tree reconstructed from the table-indent encoding), X/Twitter (DOM-only via data-testid anchors — no internal API calls), Zenn, Qiita, and claude.ai conversations via its internal API — preserving the thinking blocks, tool_use entries, and branch structure that DOM scraping loses. Everything else falls back to Readability. An optional preview window lets you trim cruft before anything is written, and an artifacts-only mode extracts just the code Claude wrote from a long chat.

Honest positioning: "Web to Markdown" is a crowded category — LLMFeeder and Save are mature options. The niche that seemed empty is "write directly into your AI agent's context files, with URL routing, claude.ai capture, and an MCP-pull alternative" — that's what I targeted.

100% local, no telemetry, MIT licensed, 184 tests, real-Chrome e2e per release.
